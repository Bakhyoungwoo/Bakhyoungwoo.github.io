05트러블 슈팅
Troubleshooting장시간 매출 분석으로 인한 API 응답 지연
문제
FastAPI가 CSV 처리·데이터 병합·통계 분석·AI 추론을 모두 끝낸 뒤 응답하는 동기 구조. 분석 시간만큼 HTTP 요청이 유지되고, 요청이 몰리면 일반 API까지 지연.
진단
장시간 분석이 HTTP 요청 내부에서 실행되며 일반 API와 같은 실행 환경을 공유. CPU 집약적인 처리와 추론이 요청 처리 자원을 점유해 분석 시간에 비례해 응답 시간이 증가.
해결
기존 · Client → FastAPI → 매출 분석 → 결과 반환
개선 · Client → FastAPI → Redis Queue → Celery Worker → 매출 분석
  1. FastAPI는 요청을 Redis Queue에 등록하고 Job ID를 즉시 반환
  2. CPU 사용량이 높은 작업은 Celery Worker가 전담, API 서버와 독립적으로 Worker 수 확장
  3. Job API로 상태 조회, 60초 주기로 queued 20분·running 15분 초과 작업을 FAILED 처리
결과
  • 동시 분석 요청 50건: p50 200.2s → 2.8s (98.6%↓), p95 221.4s → 4.3s (98.1%↓)
  • 요청 스레드 장시간 점유 해소, Worker 수 조절로 처리량 확장 구조 확보
배운 점
비동기 시스템은 큐에 넘기는 것으로 끝나지 않고, 상태 관리·실패 처리·정체 작업 정리까지 설계해야 안정적으로 운영된다.
