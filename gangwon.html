01프로젝트 소개

사용자의 여행 조건과 선호를 분석해 관광지·음식점·숙소를 검색하고, AI가 개인 맞춤형 강원도 여행 코스를 생성·검증하는 여행 의사결정 지원 서비스입니다. Elasticsearch 기반 검색과 CDC 파이프라인으로 검색엔진을 구축하고, RAG를 이용해 사용자 맞춤 여행 코스를 추천합니다.

05트러블 슈팅
TroubleshootingRDB 검색 병목과 Elasticsearch 인덱스 정합성 문제
문제
AI 코스 생성 중 장소 후보를 PostgreSQL에서 반복 조회하면서 복합 조건 검색 부하가 증가, 검색 응답과 코스 생성 시간이 함께 지연.
진단
다양한 조건의 문자열 검색·다중 필터링이 RDB에 집중. Elasticsearch 도입 후에는 PostgreSQL 변경이 인덱스에 자동 반영되지 않는 정합성 문제도 발생.
해결
  1. 검색 구조 개선 — 검색 부하를 트랜잭션 DB에서 분리해 Elasticsearch 통합 인덱스와 복합 조건 검색 API로 전환
  2. CDC 파이프라인 — PostgreSQL을 원본으로 두고 Debezium이 변경을 Kafka로 발행, Spring Kafka Consumer가 인덱스 생성·수정·삭제
  3. 장애 복구 검증 — ES를 약 20초 중지하자 복구 후에도 미반영. 재시도(약 7초)가 장애보다 짧아 DLT로 넘어가 로그만 남은 것이 원인 → 지수 backoff로 약 61초까지 연장, DLT는 장소 ID만 기록하고 스케줄러가 DB 최신값으로 재색인해 순서 역전까지 방지
결과
  • 검색 API p95 99.3ms → 18.2ms (81.7%↓), p99 148.5ms → 26.6ms (82.1%↓), 처리량 19.8%↑
  • DB 변경 → 검색 반영 p95 1,054ms, 30회 반복 전건 반영
관측

Prometheus·Grafana — HTTP 처리량·p95·Kafka Consumer Lag 대시보드

배운 점
검색 성능은 쿼리 튜닝보다 트랜잭션과 검색을 분리하고 목적에 맞는 저장소를 고르는 문제이며, 동기화·재처리·모니터링까지 함께 설계해야 한다.
